# FERRUM и соседние механизмы

Срез 2026-10-06, issue #27. Это сравнение областей применения, не результат
сравнительного бенчмарка. Исполненные свойства FERRUM и ограничения по ядрам
определяет [граница MVP](MVP-1-BOUNDARY.md). Конфигурация поставки по умолчанию
не включает respond; runtime требует сборки `attach,apiserver`.

| Механизм | Что даёт | Где имеет смысл FERRUM | Чего FERRUM не делает |
|---|---|---|---|
| Kubernetes ValidatingAdmissionPolicy / CEL | Проверяет API-запросы внутри apiserver, без отдельного webhook-сервиса. Policy и Binding определяют проверки, область и действия Deny/Warn/Audit | Когда требуется доставлять проверяемый подписанный PolicyBundle и связывать admission и runtime общими политиками; для одних проверок полей Pod VAP требует меньше компонентов | Не заменяет универсальную CEL-политику, не убирает зависимость admission от доступности webhook, не является встроенным механизмом apiserver |
| Kyverno | Политики валидации, мутации, генерации и очистки ресурсов, проверки образов; admission и фоновые проверки | Когда центральный контракт — offline compile, caller-supplied trust roots, подпись bundle и LKG при потере CP, плюс runtime-политика в том же формате | Не предоставляет эквивалент всего языка и каталога Kyverno, общего mutate/generate/cleanup и фоновой оценки всех существующих ресурсов |
| Tetragon | Наблюдение ядра и runtime enforcement; сигналы процессу и изменение возвращаемого значения имеют разную семантику и ограничения точек подключения | Когда требуется единый подписанный артефакт для admission и runtime с явной совместимостью по digest/ABI и offline trust roots | Не предоставляет сопоставимую широту kernel hooks, network visibility и готовых runtime-политик. В текущем дереве LSM предотвращает exec; file_open/sb_mount не реализованы. Tracepoint + userspace SIGKILL не предотвращает уже выполненную операцию |

LKG сохраняет ранее принятую политику, но не означает бессрочную свежесть метаданных,
не обходит проверку подписи и не делает недоступный webhook доступным. Закрытый
контур не является исключительным свойством FERRUM: все три альтернативы могут
развёртываться пользователем; сетевые зависимости конкретных политик, реестров,
проверок подписей и обновления артефактов следует оценивать отдельно. Внешнего
сравнительного пилота пока нет (#28).

Источники для свойств альтернатив, проверены 2026-10-06:

- [Kubernetes: Validating Admission Policy](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/).
- [Kyverno: Introduction](https://kyverno.io/docs/introduction/).
- [Tetragon: Enforcement](https://tetragon.io/docs/concepts/enforcement/).

Для оператора выбор начинается с задачи: проверкам Kubernetes-объектов достаточно
admission-механизма; наблюдение и запрет операций уже запущенного процесса требуют
runtime-механизма. Связка обоих не доказывает полноту каждого из них.
