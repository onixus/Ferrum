# FERRUM — план развития

Статус: черновик. Ни одна строка этого документа не является утверждением
о том, что уже сделано; утверждения о сделанном живут в
[docs/MVP-1-BOUNDARY.md](docs/MVP-1-BOUNDARY.md) и держатся гейтом. Здесь —
что делать дальше и в каком порядке, с критерием закрытия у каждой фазы. Фаза
закрыта, когда закрыт её критерий, а не когда кончились силы.

## Исходная оценка

Инверсная зрелость: методологическая дисциплина уровня production при
интеграционной зрелости уровня прототипа. Компоненты и стык доказаны,
система — нет: ни один компонент не работал в живом кластере, admission не
принимал AdmissionReview от настоящего apiserver, controller не делал rollout,
агент не наполнял cgroup-индекс с настоящего kubelet.

Десять пунктов, по убыванию тяжести:

1. **TRL 4–5.** Система существует как манифесты, прошедшие lint, и стык,
   прошедший CI. Интеграционный слой apiserver ↔ webhook ↔ controller ↔ agent
   не исполнялся ничем.
2. **Реактивный enforcement.** Датапейс — tracepoint `sys_enter` + `SIGKILL`
   из userspace. `execve` к моменту сигнала завершился; это detect-then-kill,
   а не prevent. Индустрия (Tetragon, KubeArmor) на BPF LSM с синхронным
   `-EPERM`. RFC-02 это признаёт («LSM на pin path и in-kernel drop не
   реализованы»); признание не контрмера.
3. **TOCTOU на чтении пути.** Путь читается из user memory на `sys_enter` —
   double-fetch. Fail-closed на `path_unknown` закрывает нечитаемую страницу,
   не подменённую. Закрывается тем же LSM (п. 2): хук видит dentry, а не
   указатель.
4. **Fail-closed admission = риск доступности кластера.** Упавшие реплики
   webhook с `failurePolicy=Fail` останавливают создание pod'ов в scope.
   Blast radius не документирован, break-glass из threat model не реализован,
   HA-профиля нет.
5. **Нулевая интеграция с SOC.** Экспорт — JSONL на диск. `/metrics` нет
   (`events_dropped_total` существует, но заперт внутри), syslog/CEF нет,
   схема события не формализована как контракт. Enforcement, который молча
   убивает процессы и не отчитывается в SIEM, для SOC — источник инцидентов.
6. **Все утверждения самозаверенные.** Jenkins локальный. 21 зелёная стадия —
   недоказуемое снаружи утверждение. Публичного CI, releases, образов в
   registry, SBOM, SECURITY.md нет. Продукт про верифицируемость поставляется
   неверифицируемым.
7. **Матрица ядер не определена.** Два стенда уже дали два расхождения
   (aarch64 без `open`, Firecracker без module-tracepoint'ов). RHEL, Ubuntu
   LTS, Astra Linux SE не мерялись ничем.
8. **Позиционирование не сформулировано.** VAP/CEL — GA с 1.30 и частично
   дублирует admission-половину. Ответ (подписанные bundle, LKG, fail-closed,
   admission+runtime одной политикой, офлайн trust roots) существует, но не
   артикулирован ни в одном сравнении.
9. **GPL-3.0 не проговорена как выбор.** Self-hosted не мешает; embedding и
   dual licensing — мешает. Решение принять осознанно до первого внешнего
   контрибьютора.
10. **Bus factor = 1, пользователей 0.** Все допущения о нужных политиках и
    exception workflow — гипотезы, не проверенные ни одним deployment.

## Фаза 0 — существование доказуемо

Цель: внешний человек проверяет главные утверждения за 30 минут, не веря
ни одному слову README.

- E2E в kind/k3d: развернуть controller + admission + agent из `deploy/`,
  применить `prod-restricted.yaml`, прогнать приёмку §D RFC-02 против
  настоящего apiserver: unsigned image deny, privileged deny,
  `exec`+`/bin/sh` → kill, CP down → LKG. Каждый случай — именованный тест,
  цитируемый границей, как всё остальное.
- Публичный GitHub Actions для userspace-стадий (Format, Clippy, Test,
  Checks). Датапейсные стадии остаются на Jenkins — Actions настоящего ядра
  с tracefs не даёт, и зелёная стадия, не исполнившая attach, была бы тем
  самым гейтом, умеющим себя пропустить.
- Push образов в ghcr.io, подпись cosign, SBOM (cargo-auditable + syft) как
  release-артефакт. Продукт про подписанные bundle обязан поставляться
  подписанным.
- SECURITY.md, первый tagged release, решение по лицензии зафиксировано
  в этом документе.
- Helm chart или kustomize overlay поверх `deploy/` — с гейтом
  устанавливаемости, как у самого дерева.

Критерий закрытия: `git clone` → e2e зелёный на чистой машине с kind →
образ из ghcr верифицируется cosign'ом. Всё три — без доступа к локальному
Jenkins.

## Фаза 1 — эксплуатируемость

Цель: SOC и SRE могут с этим жить.

- `/metrics`: events_dropped_total, admission latency histogram, bundle
  digest как label, degraded reasons. Grafana dashboard в дереве.
- Событийный сток наружу: syslog/CEF минимум; схема `EventEnvelope`
  формализована как версионированный контракт для SIEM, нормализация
  написана для 2–3 систем.
- HA admission: 2+ реплики, PDB, anti-affinity, exempt kube-system через
  namespaceSelector. Latency budget заявлен числом и меряется бенчмарком
  в CI; p99, который не меряется, не заявляется.
- Break-glass из threat model реализован, с journal'ом. Runbook: webhook
  упал / агент degraded / bundle не грузится. Blast radius документирован.

Критерий закрытия: инцидент «respond убил не тот процесс» расследуется
из SIEM без доступа к ноде.

## Фаза 2 — превентивный enforcement

Цель: закрыть пп. 2–3 до того, как их покажут на демо.

- BPF LSM датапейс вторым режимом: `bprm_check_security` для exec,
  `sb_mount` для mount, `file_open` — синхронный deny вместо SIGKILL.
- Tracepoint-режим остаётся fallback'ом для ядер без `CONFIG_BPF_LSM`,
  с честным статусом деградации — по образцу существующих `DEG_`.
- Матрица ядер: RHEL 9, Ubuntu 22.04/24.04, Astra Linux SE. CO-RE, если
  его ещё нет; поведение на ядре без BTF названо, а не подразумевается.
- In-kernel rate limiting против syscall flood — контрмера из RFC-02 §C,
  которая сейчас существует только как строка таблицы.

Критерий закрытия: политика по exec на LSM-режиме предотвращает запуск
(`execve` возвращает `-EPERM`), и это исполнено на настоящем ядре тестом,
процитированным границей.

## Фаза 3 — рынок (параллельно, с фазы 1)

Цель: продукт понимает, кому он нужен.

Wedge — воздушный зазор: caller-supplied trust roots, ноль обращений в
Rekor/CT, офлайн PKI, LKG при потере CP. Это спроектировано для закрытых
контуров, и сегмент — КИИ/ГИС/ЗОКИИ, где SaaS-зависимые CNAPP не проходят
по модели поставки.

- Маппинг политик на Приказ ФСТЭК № 118 (требования к средствам
  контейнеризации) — тем же форматом, что CIS 5.x/MITRE в RFC-02.
- Сравнения «vs VAP/CEL», «vs Kyverno», «vs Tetragon» — честные, с колонкой
  «чего FERRUM не делает».
- Один дизайн-партнёр с закрытым контуром. Вход — observe-режим, respond
  выключен: низкорисковый пилот и есть продуктовая функция.

Критерий закрытия: один внешний deployment и один документ обратной связи
от него в дереве.

## Не делаем сейчас

- wasm-правила: ABI лежит, хост не развивается, пока фазы 0–2 открыты;
- UI/консоль;
- multi-cluster;
- сертификация ФСТЭК как процесс — дорого и рано. Архитектурные решения
  фаз 1–2 принимаются с оглядкой на неё: журналирование, контроль
  целостности, разграничение доступа.
